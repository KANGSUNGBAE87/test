현재 빌드의 데이터 처리 요약

현재 빌드는 실제 광고, 실제 결제, 별도 분석 SDK를 사용하지 않습니다. 앱은 게스트 모드로도 이용할 수 있으며, 사용자가 로그인 또는 로컬 플레이어 프로필 연결을 선택하면 데일리/주간 챌린지 기록판을 위해 Supabase 백엔드가 사용될 수 있습니다. 앱은 게임 진행을 위해 아래 정보를 사용자의 기기 내부 저장소에 저장합니다.

  • 로컬 플레이어 프로필 식별자와 게스트 플레이 상태
  • 언어 설정
  • 사운드, 햅틱, 꾸미기 장착 상태 같은 설정
  • 팝조각, 보유 꾸미기, 부스터, 경제 사용/획득 로그
  • 스테이지 클리어, 별, 최고 기록, 오늘/주간 도전 기록
  • 출석 보상과 일일 미션 상태

로그인된 사용자끼리의 챌린지 기록판을 사용할 때는 챌린지 종류, 챌린지 날짜/주차 키, 보드 seed, 클리어 시간, 탭 수, 별 개수, 부스터/이어하기 여부, 앱 버전, 표시 이름, 앱 내부 사용자 식별자, Supabase 인증 사용자 ID가 Supabase에 저장될 수 있습니다. 일반 스테이지 진행도, 팝조각, 꾸미기, 부스터, 출석, 미션 상태는 별도 동기화 기능을 켜기 전까지 기기 내 처리에 머뭅니다.

권한과 기기 기능

현재 Android 제출 빌드는 인터넷 권한과 진동 권한을 포함합니다. 인터넷 권한은 앱 콘텐츠 제공과 로그인 챌린지 기록판 연동에 사용될 수 있습니다. 진동 권한은 팝 효과를 위한 기기 진동에만 사용됩니다. 앱은 팝 효과를 위해 기기의 오디오 출력과 진동 기능을 사용할 수 있으나, 카메라, 마이크, 위치, 연락처, 문자, 통화 기록, 사진/동영상 파일, 광고 ID 권한을 요청하지 않습니다. No Advertising ID permission is used in the current build.

이용 목적

저장 정보는 게임 진행도 유지, 설정 유지, 모드 기록 표시, 출석과 미션 상태 계산, 팝조각 보상과 소비 내역 확인, 로그인 사용자 간 데일리/주간 챌린지 기록판 제공을 위해 사용됩니다.

Current Build Data Handling Summary

The current build does not use live ads, live purchases, or separate analytics SDKs. The app can still be used in guest mode. If the user chooses sign-in or links a local player profile, Supabase may be used to provide the signed-in Daily/Weekly Challenge leaderboard. The app stores the following information on the user's device to maintain gameplay:

  • Local player profile identifier and guest play state
  • Language setting
  • Settings such as sound, haptics, and equipped cosmetics
  • Pop Pieces, owned cosmetics, boosters, and economy earn/spend logs
  • Stage clears, stars, best records, and daily/weekly challenge records
  • Daily reward and daily mission state

When the signed-in challenge leaderboard is used, the app may store the challenge kind, challenge date/week key, board seed, clear time, tap count, star count, booster/continue flags, app version, display name, internal app user identifier, and Supabase authenticated user ID in Supabase. Regular stage progress, Pop Pieces, cosmetics, boosters, daily reward, and mission state remain processed on device unless a separate sync feature is enabled later.

Permissions and Device Features

The current Android submission build includes Internet and vibration permissions. Internet access may be used to serve app content and connect the signed-in challenge leaderboard. The vibration permission is used only for device vibration during pop effects. The app may use device audio output and vibration for pop effects, but it does not request camera, microphone, location, contacts, SMS, call logs, photos/videos, or Advertising ID permission. No Advertising ID permission is used in the current build.

Purpose

Stored information is used to keep gameplay progress, preserve settings, show mode records, calculate daily rewards and missions, review Pop Piece earn/spend history, and provide signed-in Daily/Weekly Challenge leaderboards.

Third Parties and SDKs

The current Google Play submission build does not connect AdMob, Google Play Billing, Firebase Analytics, Crashlytics, ad mediation SDKs, or a separate analytics SDK. Supabase may be used as the backend provider for the signed-in challenge leaderboard.

The app is packaged as a Capacitor Android WebView app. The project may include Apps in Toss compatibility dependencies, but the current Google Play submission build does not enable Toss login, Apps in Toss ads, Apps in Toss payments, Apps in Toss game user keys, Google sign-in, Google Play Billing, or Advertising ID usage.

Retention and Deletion

Local player profile and most gameplay data are retained on the user's device. Users can remove local data by clearing app data in Android settings or uninstalling the app. Users can request deletion of server-side signed-in challenge leaderboard records by contacting the privacy email.

The current build does not create server accounts for purchases or paid entitlements.

Security

The current build does not store sensitive account tokens, payment information, advertising identifiers, location information, or contacts in the app. Supabase service role keys, database passwords, and server secrets are not bundled in the app. If purchases are added later, token exchange, receipt validation, and entitlement handling should be processed server-side.

Children

크레이지 뽁뽁이 is not currently positioned as an app specifically directed to children. If that changes, Google Play Families policy, ads, and data requirements need a separate review.

Changes

When Google sign-in, Toss login, Apps in Toss game user keys, AdMob, Apps in Toss ads, Google Play Billing, Apps in Toss payments, analytics/crash reporting, stage-calibration telemetry, or full progress sync are added, this policy and the Play Console Data safety declaration should be updated together.
