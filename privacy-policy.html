Current Build Data Handling Summary

The current Google Play submission build does not use account creation, live ads, live purchases, analytics SDKs, or a remote progress-sync server. The app stores the following information on the user's device to maintain gameplay:

  • Local player profile identifier and local sign-in state
  • Language setting
  • Settings such as sound, haptics, and equipped cosmetics
  • Pop Pieces, owned cosmetics, boosters, and economy earn/spend logs
  • Stage clears, stars, best records, and daily/weekly challenge records
  • Daily reward and daily mission state

The current build is not configured to send this information to a developer server or third parties. For Google Play Data safety purposes, the current build's gameplay data remains processed on device.

Permissions and Device Features

The current Android build includes the Internet permission for the Capacitor/WebView app shell and future platform integration paths. The current build does not upload gameplay data to a developer server. The app may use device audio output and vibration for pop effects, but it does not request camera, microphone, location, contacts, SMS, call logs, photos/videos, or Advertising ID permission. No Advertising ID permission is used in the current build.

Purpose

Stored information is used to keep gameplay progress, preserve settings, show mode records, calculate daily rewards and missions, and review Pop Piece earn/spend history.

Third Parties and SDKs

The current Google Play submission build does not connect AdMob, Google Play Billing, Firebase Analytics, Crashlytics, ad mediation SDKs, or a separate analytics SDK. The current build is also not configured to share user data with a developer server or third-party server.

The app is packaged as a Capacitor Android WebView app and may include an Apps in Toss framework dependency for a later Apps in Toss release path. In the current Google Play submission build, Toss login, Apps in Toss ads, Apps in Toss payments, Google sign-in, Google Play Billing, and Advertising ID usage are not enabled.

Retention and Deletion

Local player profile and gameplay data are retained on the user's device. Users can remove local data by clearing app data in Android settings or uninstalling the app. Depending on the user's device or Google account settings, Android system backup/restore may process app data, but the developer does not separately collect that data on a server in the current build.

The current build does not create server accounts, so there is no separate server account deletion process.

Security

The current build does not store sensitive account tokens, payment information, advertising identifiers, location information, or contacts in the app. If sign-in or purchases are added later, token exchange, receipt validation, and entitlement handling should be processed server-side, and secrets must not be bundled in the app.

Children

크레이지 뽁뽁이 is not currently positioned as an app specifically directed to children. If that changes, Google Play Families policy, ads, and data requirements need a separate review.

Changes

When Google sign-in, Toss login, Apps in Toss game user keys, AdMob, Apps in Toss ads, Google Play Billing, Apps in Toss payments, analytics/crash reporting, or backend progress sync are added, this policy and the Play Console Data safety declaration should be updated together.
